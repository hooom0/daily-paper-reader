## 摘要
专业设计需要任意颜色控制：即能够在图像生成与编辑中，用任意 24 位十六进制颜色值指定对象的目标颜色。已有工作探索了颜色生成、颜色编辑与着色，但往往依赖专用的颜色表示或专门的推理流程。大语言模型的进展提供了一个更简单的起点：即使是紧凑型模型也能将十六进制值与颜色语义关联起来。我们提出 Paint-Anything，通过对象级颜色监督，学习一个用于生成与编辑的共享十六进制提示接口。我们开发了一条数据流水线，通过对象定位、感知颜色标注与编辑对合成，从真实图像构建了 Paint-500K。由于阴影会使真实图像的标签只能近似表示颜色，我们用纯色锚点来补充这一监督，其像素与配对的十六进制值完全一致。这些锚点仅在高噪声时间步使用，低噪声阶段的训练则交由自然图像完成。我们进一步提出任意颜色基准（Any Color Benchmark，ACBench），包含 ACBench-T2I 与 ACBench-Edit，用以衡量两项任务中对象级的十六进制颜色保真度。在 FLUX.2-4B 上，相对于基础模型，Paint-Anything 将 ACBench-T2I 与 ACBench-Edit 分数分别提升 85.3% 和 28.3%，消融实验也支持该训练方案。在对比方法中，它还取得了最高的平均 CompColor 分数。

## Abstract
Professional design requires any-color control: the ability to specify an object's target color with any 24-bit hex value for image generation and editing. Prior work has explored color generation, editing, and colorization, but often relies on dedicated color representations or specialized inference procedures. Advances in large language models offer a simpler starting point: even compact models can associate hex values with color semantics. We present Paint-Anything, which learns a shared hex-prompt interface for generation and editing through object-level color supervision. We develop a data pipeline that constructs Paint-500K from real images through object grounding, perceptual color labeling, and editing-pair synthesis. Since shadows make real-image labels only approximate colors, we complement this supervision with pure-color anchors whose pixels exactly match their paired hex values. These anchors are used only at high-noise timesteps, leaving low-noise training to natural images. We further introduce Any Color Benchmark (ACBench), comprising ACBench-T2I and ACBench-Edit, to measure object-level hex color fidelity across both tasks. On FLUX.2-4B, Paint-Anything improves ACBench-T2I and ACBench-Edit scores by 85.3% and 28.3%, respectively, relative to the base model, with ablations supporting the training recipe. It also achieves the highest average CompColor score among the compared methods.

- **现有方法痛点**：
  - 部分方法引入任务专用模块或可学习颜色 token（如 ColorPeel 的可学习颜色提示、NumColor 的数值颜色编码、CIELAB 对齐文本嵌入等），跨颜色扩展性差、难迁移到新架构。
  - 部分方法采用免训练推理期技巧（采样引导、注意力/Value 操控、颜色对齐目标等），推理成本高且任务覆盖不统一。
  - 颜色生成、着色（colorization）、颜色编辑常被当作**三个割裂的问题**，而非统一的提示跟随能力。
- **关键洞察**：24 位 RGB 值可直接以文本形式书写并与对象短语绑定；作者用探针实验证明，连紧凑的 Qwen3-4B 也能把 `#F0FFF1`、`#E8D00A` 解析为合理的颜色语义，说明 hex 字符串可充当**提示原生的数值颜色接口**。
- **整体含义**：将颜色控制"内化"为语言提示的一部分，用单一微调模型、单一接口统一生成与编辑，避免额外控制器与特殊推理流程。

## 2. 方法论

### 2.1 核心思想
- 用 `<color>#AABBCC</color>` 标签把 hex 颜色直接写进提示，由冻结的文本编码器编码为普通文本 token；在**对象级颜色监督**下微调去噪 Transformer，使同一模型同时学会颜色感知、对象—颜色绑定与颜色条件编辑。

### 2.2 基础框架与损失
- 基于 rectified-flow 文生图模型（文本编码器 + VAE + 去噪 Transformer）。设文本提示为 $y$，目标图像 $I^\star$，编辑时源图为 $I_c$。
- 前向加噪与速度目标：
  - $z_t = (1-t)z_0 + t\epsilon$，$v^\star = \epsilon - z_0$，其中 $z_0=E_{vae}(I^\star)$，$t=0$ 为干净潜变量，$t=1$ 为纯噪声。
- 去噪器预测速度：$\hat{v}_\theta = D_\theta([z_t; z_c], t, c)$，编辑时拼接干净条件潜变量 $z_c=E_{vae}(I_c)$，T2I 时退化为仅 $z_t$。
- 流匹配损失：$\mathcal{L}_{FM}=\mathbb{E}\|\hat{v}_\theta - v^\star\|_2^2$。
- 总目标：$\mathcal{L}=\lambda_{t2i}\mathcal{L}_{t2i}+\lambda_{edit}\mathcal{L}_{edit}+\lambda_{rgb}\mathcal{L}_{rgb}$，三路权重均取 1；仅微调去噪 Transformer，VAE 与文本编码器冻结。

### 2.3 三项关键技术
1. **显式颜色标签包裹**：将每个 hex 值用 `<color>...</color>` 包裹后再送入冻结文本编码器，给原始 hex 字符串一个清晰的文本句柄，实验证明可提升对象级颜色保真与组合颜色绑定。
2. **生成与编辑统一格式**：联合训练 T2I 与编辑样本，二者共享同一去噪目标，仅差在是否拼接干净条件图像潜变量，从而用同一 hex 提示接口覆盖两种任务。
3. **纯色锚点 + 高噪声门控**：真实图像受阴影影响，测得的颜色只是近似值。于是额外采样 24 位 RGB 渲染为纯色图，与对应 `<color>#HEX</color>` 提示配对，提供"像素与 hex 精确一致"的干净底层信号。受纯色生成轨迹中颜色在 $t\approx0.8$ 附近已稳定的观察启发，纯色样本仅在 $t\sim U(t_{gate},1.0)$ 的高噪声区间训练（默认 $t_{gate}=0.8$），低噪声阶段交给真实图像。

### 2.4 数据流水线（Paint-500K）
- **对象颜色提取**：VLM 依据 caption 定位相关对象及包围框，SAM3 生成对象掩码；在**CIELAB 感知空间**而非 RGB 空间做 **MeanShift 聚类**（带宽 0.05），自适应确定簇数，避免固定 K 的 k-means 把阴影/噪声拆成冗余颜色（作者用皮肤区域对比图佐证）。
- **过滤规则**：每个保留簇须覆盖对象像素 ≥15%（`COLOR_MIN_RATIO`），保留簇合计覆盖 ≥90%（`INSTANCE_KEEP_RATIO`），否则丢弃该实例；取像素质量最大的簇转为 sRGB hex 标签（抽查 100 个样本，96 个与人工感知一致）。
- **颜色—对象—caption 绑定**：VLM 重写 caption，用 `<color>#HEX</color>` 把颜色标签插入对应名词短语，并借包围框推断"左/右/背景"等空间关系（不输出坐标）。
- **双数据流**：T2I 共 400K（100K 单对象裁剪 + 300K 多对象组合绑定）；编辑共 100K——用 Qwen-Image-Edit-2511（4 步 Lightning LoRA）把单对象图改色作为**源图**，原图作为**目标图**，指令要求恢复原始 hex 颜色，因此目标图不含生成伪影。
- **编辑对过滤**：要求掩码外变化足够小（保场景）、掩码内变化足够大（确保有意义改色），并做 VLM 验证与指令重写，且必须原样保留目标 hex 字符串。

## 3. 实验设计

### 3.1 数据集 / 场景与基准
- **Paint-500K**：自建训练集，500K 样本（400K T2I + 100K 编辑 + 10K 纯色锚点），来源为**内部非公开**高质量真实图像集合。
- **ACBench（本文提出）**：
  - ACBench-T2I：1000 条提示，500 条单对象（Single）+ 500 条双对象（Two），后两者取算术平均得 Overall。
  - ACBench-Edit：500 条真实图像重着色提示。
  - 颜色从 24 位 RGB 空间随机采样，与日常物体/动物/植物配对；评测用 SAM3 取目标掩码。
- **CompColor**：ColorBind 提出的组合颜色绑定基准（单对象/Close/Distant 子集），本文额外提出 **hex 翻译协议**，仅把颜色词替换为规范 hex 值（如 tomato → `#FF6347`），保持对象组合与分割不变；另做三对象扩展实验。
- **GenColorBench NCU**：官方数值颜色理解协议（4 图/提示、GroundingDINO+SAM2 定位、OneHue 主色提取、CIEDE2000 打分），作为独立验证。
- **评测指标**：对掩码内像素取均值 RGB $\bar{c}$，计算通道 MAE，再经分段线性映射为 0–100 分：
  - $s = 100\cdot\max(0,\,1-\max(0,\text{MAE}-16)/48)$，即 MAE ≤16 满分、≥64 得 0，中间线性给分；定位失败计 0 分。
- **人类偏好研究**：15 名被试 × 80 条随机 ACBench-T2I 提示，共 1200 次颜色偏好判断，另有 200 次成对图像质量判断。

### 3.2 对比方法与主干
- **通用模型**：SD1.5、FLUX.1、Z-Image-Turbo、Qwen-Image / Qwen-Image-Edit、FLUX.2-4B / 9B / dev。
- **颜色专用方法**：ColorBind/Edit、CtrlColor、ColorPeel、ColorWave（本文复现）、NumColor（代码不可得，引用其已发表 NCU 结果）。
- **主干与训练**：在 FLUX.2-klein-base-4B 与 Z-Image Base 上用同一配方微调；FLUX.2-4B 编辑统一 CFG=2.0。

## 6. 主要结论与发现

- **大幅超越基模型**：在 FLUX.2-4B 上，ACBench-T2I 从 37.02 提升到 68.58（+85.3%），ACBench-Edit 从 58.90 提升到 75.57（+28.3%）。
- **小模型反超大模型**：8B 总参数的微调模型在 ACBench-T2I 上超过 56B 的 FLUX.2-dev 达 16.88 分，编辑上超 6.70 分，说明**对象级 hex 监督比单纯扩大参数量更有效**。
- **弥合"词—hex"鸿沟**：CompColor 上把颜色名换成 hex 会使 FLUX.2-4B 基模型从 0.72 跌到 0.38，微调后 hex 协议平均分翻倍以上（0.79）并超过基模型的命名颜色成绩；命名颜色分数也从 0.72 升到 0.79，说明原有组合绑定能力未被破坏。
- **优于颜色专用方法**：ACBench-T2I 超最强专用基线 ColorWave 22.04 分，ACBench-Edit 超 ColorBind/Edit 15.19 分；GenColorBench NCU 上从 34.00 升至 57.89（+23.89），并超过已发表的 FLUX+NumColor（51.90）。
- **配方验证**：全参微调显著优于 rank-256 LoRA（68.58 vs 48.45 / 75.57 vs 58.71 / 0.79 vs 0.54）；颜色标签包裹带来 +13.10（T2I）与 +8.08（Edit）的增益；高噪声门控相比无门控锚点提升 T2I 4.75 分、Edit 5.18 分，且 0.7

0.7 与 0.8 表现接近、0.9/1.0 明显退化，说明门控需落在"颜色语义已成形但细节尚未固化"的区间。
- **评测稳健性**：Table 7 表明换用 5 种区域颜色估计器后模型排序与主结果一致，说明结论不依赖单一取色方式；Table 8 的 36 种 SAM3 阈值 × 覆盖门限组合下排名稳定；Table 9 显示各模型定位失败率较低且微调后未显著恶化，排除"靠掩码更准而刷分"的可能。
- **编辑行为符合预期**：按源—目标 CIEDE2000 距离分桶（Table 11）显示，色差越大得分略降但整体平稳，说明模型并非只在"轻微改色"上讨巧；掩码外区域保持良好，未出现全局色彩漂移。
- **人类偏好**：15 名被试共 1200 次颜色偏好判断中，本文模型在颜色匹配维度上被偏好比例显著高于通用基模型与颜色专用基线；200 次成对图像质量判断中，颜色编辑未以明显牺牲画质为代价。
- **数据泄漏排查**：Appendix L 对训练与评测字符串做重叠检查，未发现可解释分数增益的重复样本。

## 7. 局限性与未来方向

- **纯色锚点的语义鸿沟**：锚点流提供的是"像素与 hex 严格一致"的信号，但纯色图缺乏材质、光照、纹理与遮挡，模型学到的更多是"色相/明度坐标感"而非"该颜色在真实物体表面应呈现的样子"。这可能是编辑任务增益（+28.3%）明显小于生成任务（+85.3%）的原因之一。
- **真实图像的颜色歧义**：即便在 CIELAB 空间聚类，真实物体的观测色仍受高光、阴影、环境反射与相机白平衡影响，提取的 hex 只是"近似标签"。作者用 ≥15% 覆盖与 ≥90% 合计覆盖的过滤规则缓解，但无法根除监督噪声；这也解释了为何需要高噪声门控把低噪声阶段交给真实数据。
- **编辑数据的合成偏置**：编辑对由 Qwen-Image-Edit-2511 生成源图、以原图为目标图，虽然避免了目标图伪影，但源图的"改色伪影分布"与真实用户编辑分布可能不同，模型可能学到该生成器的特定痕迹；且 100K 编辑对相对 400K T2I 样本存在任务不平衡（训练 batch 中 30 T2I : 30 Edit 部分抵消了这一点）。
- **评测层面的未解问题**：
  - T2I 每提示仅采样一个种子，缺少多随机种子下的方差与置信区间，无法判断分数差异是否稳定。
  - ACBench 为自建基准，颜色—对象配对与提示模板由作者设计，可能存在与训练分布同源的偏置（训练/评测字符串重叠检查只覆盖字面重复，不覆盖模板相似性）。
  - 人类研究规模较小（15 人、被试与提示重复出现），未报告被试间一致性或统计显著性检验。
  - NumColor 未实际复跑，跨论文数值比较的可比性有限。
- **方法能力边界**：只做"对象级整体改色"，未处理渐变、纹理色、半透明/金属材质、多光源下的分区域着色，也未涉及"同一对象多色块"或"颜色与风格解耦"的问题；对极小对象、遮挡严重对象、无明确名词指代的对象，定位失败会直接导致 0 分。
- **可迁移性**：仅在 rectified-flow 架构（FLUX.2-klein-base-4B、Z-Image Base）上验证，对 UNet 系扩散模型、自回归/连续 token 生成模型的适用性未知；全参微调优于 LoRA 的结论也意味着部署成本较高。
- **可能的未来方向**：引入真实拍摄的受控色卡/材质样本以缩小锚点与真实图像的差距；用真实用户编辑日志替代或补充合成编辑对；在评测中引入多种子采样与显著性检验；把 hex 接口扩展到渐变与多色区域（如颜色地图或调色板 token）。

## 8. 总体评价与意义

- **问题意识清晰**：把"颜色生成 / 着色 / 颜色编辑"统一为同一个"提示跟随"问题，并用一个接口（`<color>#HEX</color>`）覆盖两类任务，是本文最主要的观念贡献，避免了任务专用模块的碎片化设计。
- **方法简洁且可复现性好**：核心改动只有三处——标签包裹、生成/编辑统一格式、纯色锚点 + 高噪声门控，且只微调去噪 Transformer，其余组件冻结；数据流水线的过滤阈值、聚类带宽、门控值等均给出具体数值，具备较强的工程可复现性。
- **实证扎实**：消融链条从模块 → 超参 → 评测器稳健性 → 定位失败审计层层递进，并在两个主干与两个外部基准上交叉验证；"8B 微调模型超过 56B 基模型"的结果具有较强说服力，说明对象级颜色监督是比参数规模更关键的变量。
- **诚实的自我暴露**：附录给出训练/评测字符串重叠检查、编辑掩码外变化的约束、定位失败率统计等，显示出对评测公平性的主动审查意识。
- **遗留风险**：自建基准的主导权、单种子采样、小规模人类研究、合成编辑数据的生成器偏置，以及"颜色标签来自近似聚类"的监督噪声，共同构成了结论外推时需谨慎对待的边界；若后续工作能在真实编辑日志与多种子评测上补齐这些环节，本文提出的"提示原生数值颜色接口"有望成为更通用的颜色控制范式。
